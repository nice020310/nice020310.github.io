今日学习记录：Softmax、交叉熵与 PyTorch Autograd

发表于2026-08-02|更新于2026-08-02|科研学习
|阅读量:

今天整理的是 2026-08-02 已经写入 Obsidian 的两部分学习内容：一部分是对 Softmax、交叉熵、链式法则与 PyTorch autograd 的集中复盘，另一部分是把当天可确认的实验结果和证据边界收紧成可公开表述的事实。这里只记录原始笔记里已经出现的学习结论、测试结果和失败案例，不补写尚未完成的训练能力或工程成果。

今天实际确认了什么

先收敛成几条当天已经能站住的判断：

  • logits 是模型输出的原始打分，不是概率分布。
  • Softmax 负责把同一样本的一组 logits 转成和为 1 的概率。
  • class-index 分类里的交叉熵，本质上是对真实类别概率取负对数。
  • PyTorch cross_entropy 接收的是未归一化的 logits，而不是先做完 Softmax 的概率。
  • autograd 通过 requires_grad 追踪计算图，再由 backward() 按链式法则回传梯度。
  • target 在 class-index 场景下必须是 torch.long；若误传 float，会直接触发 dtype 错误。

今天能说到哪一步，不能说到哪一步

当天笔记对证据边界写得比较克制，这一点值得保留。

目前可以公开确认的是：

  • 公式层面的最小例子已经被手算和测试同时验证。
  • requires_grad、backward()、grad 和 cross_entropy 的基础接口约束已经在小样例上跑通。
  • float target 导致的 dtype 错误已经被真实复现，并能通过 torch.long 修复。

但同样不能把这一天的学习扩写成以下结论：

  • 不能据此声称已经完成完整训练循环。
  • 不能据此声称已经验证模型收敛。
  • 不能据此声称已经完成 GPU 性能实验。
  • 不能据此声称已经通过 PyTorch 的独立限时考核。

原因很直接：当天全部证据仍然来自固定 CPU 的小样例、聚焦测试和接口级故障复现。它足以说明概念和 API 约束正在被收紧，但还不足以证明更大规模训练与性能结论。

还缺什么

按原始笔记，当前仍然明确未完成的内容包括：

  • 数学正式维度 20 题与 90% 考核尚未完成。
  • 概率与梯度的综合题仍未完成。
  • PyTorch 方向还缺 Tensor 操作、广播、nn.Module、训练循环、显存与 profiler。
  • C++ 方向仍缺独立限时 B 门与独立 T 门。

因此，今天更准确的定位不是“已经掌握完整深度学习训练链路”，而是“先把 Softmax、交叉熵、链式法则和 autograd 的最小闭环搞清楚，并把一个常见 dtype 坑踩实了”。

明天的衔接点

原始笔记已经给出了下一学习块：

  • PyTorch Tensor
  • 广播
  • nn.Module
  • loss shape 故障

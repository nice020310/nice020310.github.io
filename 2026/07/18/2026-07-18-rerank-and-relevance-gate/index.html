多媒体取证 Agent 学习笔记：Day 3 加入 Cross-Encoder Rerank 与证据不足拒答

发表于2026-07-18|更新于2026-07-19|AI
|阅读量:

Day 2 把召回层补成了 Hybrid Retrieval，但还不够。原因很简单：RRF 只能根据排名融合候选，它并不会联合理解 query 和 chunk 之间的细粒度语义关系。

所以 Day 3 做的事，就是把问答链路从“多路召回”再往前推进一步，加入：

  • Cross-Encoder 精排
  • Relevance Gate
  • 证据不足时的生成前拒答
  • Reranker 异常时的回退策略

升级后的主链路

这里有一个很关键的思想变化：系统不再默认“只要召回到一点东西，就把上下文丢给模型总结”。如果 rerank 后最高分仍然太低，就在进入 LLM 之前直接拒答。

为什么 Rerank 和 RRF 不是重复工作

这一天把两者边界彻底说清楚了。

  • RRF 解决的是多路检索结果怎么融合，它只用 rank，不联合理解 query 和文本
  • Cross-Encoder 解决的是候选精排，它会把 query 和 chunk 一起编码，判断更细粒度的相关性

因此，RRF 更适合粗召回后的无量纲融合，Cross-Encoder 更适合小候选集上的精细排序。两者是前后串联关系，不是二选一。

这一步很重要，因为 retry、fallback 和 refuse 是三种不同语义：

  • retry 处理瞬时故障
  • fallback 处理组件暂时不可用
  • refuse 处理证据不足

如果这三类情况混在一起，系统就会既不稳定也不诚实。

这一天的实验结果

记录下来的对照结果如下：

模式 Recall@3 MRR Top-1
Hybrid RRF 1.000 0.917 0.833
Hybrid + Rerank 0.833 0.833 0.833

这组结果反而很有价值，因为它明确提醒我：Rerank 不一定在所有流量上都带来指标提升。

当前最典型的失败案例，是中文问题查询英文论文时，Hybrid 已经把正确证据排到前面，但英文 Cross-Encoder 反而把它排出 Top-3。也就是说，精排模型本身的语言适配能力，会决定它到底是在“帮忙”还是“帮倒忙”。

另一个失败点是某些困难负样本仍然能穿过当前阈值，说明 hard negatives 还不够，后面需要继续扩充校准集。

Day 3 真正解决了什么

如果只看“加了一个 reranker”，其实低估了这一天的价值。更准确的说法是：

  • 系统开始区分“召回到一些内容”和“这些内容足以支持回答”
  • 弱相关上下文不会再默认进入 LLM
  • 精排失败或超时时有明确降级路径
  • 结果状态开始可解释，而不是只看最终有没有输出文本

这一步让系统从“多路召回版 RAG”变成了“带证据门控的 RAG”，也是后面做 Workflow 节点化的必要前提。

一个更准确的总结

如果要概括 Day 3，我会这样表达：

我在 BM25 + Dense + RRF 的基础上加入了 Cross-Encoder 精排和 Relevance Gate。系统先对 Hybrid Top-10 做细粒度相关性排序，再根据校准阈值判断证据是否足够；若不足，则在调用 DeepSeek 前直接拒答。这样做的目标不是让模型“少说错话”，而是让弱相关上下文根本不要进入生成阶段。同时，Reranker 超时或不可用时会回退到 RRF 结果并显式标记 degraded，保证链路可用性。

Day 3 的关键，不是单纯“多了个模型”，而是系统第一次真正拥有了生成前的证据门控。

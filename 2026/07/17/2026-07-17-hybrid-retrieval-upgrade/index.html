多媒体取证 Agent 学习笔记：Day 2 用 Hybrid Retrieval 替换单路 Dense Top-K

发表于2026-07-17|更新于2026-07-19|AI
|阅读量:

Day 2 的核心任务很明确：把项目里原本的单路 Dense Top-K 检索，升级成 BM25 + Dense + RRF 的 Hybrid Retrieval。

原因并不复杂。前一天的实验已经证明，Dense 检索擅长语义改写，但对模型名、参数名、缩写、指标名这类精确词面并不稳定；而 BM25 正好补上这一块。真正可用的工程方案，不是二选一，而是把两条召回路线放在一起，再用合理的融合方式保留各自优势。

为什么不能直接把两种分数相加

Dense 与 BM25 的原始分数没有直接可比性。

  • BM25 通常是“分数越大越相关”
  • Chroma 距离通常是“距离越小越相关”
  • 两者数值范围和分布也不同

如果直接相加，工程意义很弱，结果还容易受语料、模型和 query 波动影响。这里更稳妥的做法是使用 RRF，只利用各自的 rank 做无量纲融合。

除了 Hybrid 主流程，这一天还有几个工程点非常重要。

第一，source 里补充了可解释字段：

这意味着后面看一个结果时，不再只知道“它被检索到了”，还知道它是被哪条路命中的、在各自列表里排第几、最终为什么能进入 Top-K。

第二，加入了单路降级。Dense 或 BM25 任一路异常时，不让整个请求直接失败，而是退化到剩余可用路线继续返回结果。

第三，保留旧 API 兼容。page_number 和 text 不动，只是在 sources 里附加解释字段，这让前端无需重写展示逻辑。

实验结果说明了什么

这一天记录的对照指标如下：

Mode Recall@3 MRR Top-1 Accuracy
Dense 0.833 0.750 0.667
Hybrid 1.000 0.917 0.833

这些数字的意义不是“Hybrid 从此完胜一切”，而是至少证明了两点：

第一，精确参数类问题确实能被 BM25 找回。某些在 Dense Top-3 里缺失的关键 chunk，通过 Hybrid 可以重新进入最终结果。

第二，Dense 依然不可替代。语义改写类问题主要还是靠 embedding 路线命中，这说明 BM25 不是替代 Dense，而是补足 Dense 的盲区。

这一天也确认了 Hybrid 的边界

Hybrid Retrieval 能解决很多单路召回问题，但它不是终点。

这一天已经明确看到几个限制：

  • 跨语言查询仍然不稳定，中文问题问英文论文时，两条路线都可能只能把正确证据排到次优位置
  • 当前没有 relevance gate，无关问题依然会被强制返回 Top-K
  • RRF 只能做粗粒度融合，不能替代 query-document 级别的细粒度语义精排

所以这一天的升级，本质上只是把“召回层”补完整，而不是把整条问答链路一次性做完。

一个更准确的总结

如果要概括 Day 2，我会这样说：

我把原来的单路 Dense Top-K 升级成了 BM25 + Dense 的 Hybrid Retrieval，并用 RRF 做无量纲融合。这样系统既能保留 embedding 对语义改写的召回能力，也能补上 BM25 对模型名、参数名和缩写等精确词面的优势。同时，我在 sources 中补充了 dense_rank、bm25_rank、rrf_score 和 matched_by 等解释字段，让检索结果不再是黑盒返回。

Day 2 的核心价值，是把检索从“单路试试看”推进到了“多路召回、可解释融合、单路可降级”的工程形态。
